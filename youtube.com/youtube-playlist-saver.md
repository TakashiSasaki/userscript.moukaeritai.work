# YouTube Playlist Saver 設計書

このドキュメントは、YouTube のプレイリストに含まれる動画 ID を記録・管理するユーザースクリプトの設計を定義します。

## 1. プロジェクトの目的

`youtube-playlist-saver.user.js` を作成し、YouTube プレイリスト内の動画情報を効率的に収集・可視化することを目的とします。

### 開発リソース
*   **サンプル DOM**: `samples/` ディレクトリに、プレイリスト全体の DOM や動画アイテムの断片を保存し、分析に使用します。
*   **実行環境**: ブラウザの Tampermonkey 拡張機能での動作を想定しています。

## 2. 動作対象ページ

URL の `list` パラメータにプレイリスト ID が含まれるページを対象とします。

*   **後で見る (Watch Later)**: `https://www.youtube.com/playlist?list=WL`
*   **高く評価した動画 (Liked Videos)**: `https://www.youtube.com/playlist?list=LL`
*   **一般のプレイリスト**: `https://www.youtube.com/playlist?list=[PLAYLIST_ID]`

## 3. ユーザースクリプトの機能

### 3.1 動画 ID の収集
*   **自動記録**: ユーザーがプレイリストをスクロールして表示された動画アイテムの ID を抽出します。
*   **プレイリスト管理**: 動画 ID は、対応するプレイリスト ID（`WL` や `LL` を含む）と紐付けて記録します。
*   **重複除外**: すでに保存済みの動画については、新規に記録しません。

### 3.2 永続データストレージ
*   収集したデータの保存および読み込みには、ユーザースクリプトの API である `GM_setValue` および `GM_getValue` を使用します。
*   **パフォーマンス最適化**:
    *   **データのキャッシュ**: ストレージへのアクセス回数を減らすため、メモリ上にデータのキャッシュを保持します。
    *   **一括保存 (Batch Save)**: データの書き込みは、バッチ処理により効率化。変更検知から2秒間の待機（デバウンス）を経て、まとめて保存されます。
*   **フィルター設定の保存**: タイトルおよびチャンネル名による絞り込みフィルターの入力値も、次回訪問時に復元されるよう自動的に保存します。
*   メタデータ項目の `@grant` には、これらの API を使用するために必要な権限を設定します。

### 3.3 既知動画のインジケーター表示
*   **表示場所**: 各動画アイテム内の `id="engagement-bar"` 要素。
*   **表示内容**:
    *   **新規**: `[NEW]` (青色) - 今回のセッションで初めて検出・記録された動画。
    *   **既知**: `[SAVED]` (緑色) - 以前のセッションですでに記録済みの動画。

### 3.4 補助機能
*   **自動スクロール**: 長いプレイリストの動画を効率的に読み込むため、画面右下に「Auto Scroll」ボタンを表示します。このボタンで自動スクロールの ON/OFF を切り替えることができます（ON時は赤色に変化）。
*   **絞り込みフィルター**:
    *   動画タイトルまたはチャンネル名の部分一致でリスト表示を絞り込むパネル機能を提供します（画面右下）。
    *   入力欄には「×（クリア）」ボタンを配置し、ワンクリックで入力をリセットできます。
    *   検索結果の「表示件数 / 全件数」を表示します。
    *   **状態表示インジケーター**:
        *   **Spinner**: YouTube の読み込み状態（スピナー）をリアルタイムで検知（`Active`/`Idle`）。
        *   **Filtering**: フィルター入力による表示絞り込み処理の実行状態（`Active`/`Idle`）。
        *   **Processing**: 動画の削除操作など、一括処理の実行状態（`Active`/`Idle`）。
        *   これにより、スクリプトが現在何らかの処理を行っているかどうかをユーザーが視覚的に確認できます。
    *   **ビューポート情報の表示**: 現在ビューポートより上にある（スクロールして通り過ぎた）動画のインデックス範囲を表示します（例: `Above: 1-20, 25-30`）。
*   **個別削除**: 各動画のインジケーター横に「ゴミ箱」アイコンを表示します。これをクリックすると、YouTube のメニューを自動操作し、その動画を現在のプレイリストから削除します。
    *   削除に成功すると、その動画行はグレーアウト（半透明化）され、操作不能になります。
    *   リストからの削除のみを行い、スクリプトが保存している動画IDデータには影響しません（安全のため）。
*   **一括削除 (Remove Above)**:
    *   フィルターパネルに「Remove Above」ボタンを配置します。
    *   現在ビューポートより上にあり、かつフィルターで表示されている動画を一括でプレイリストから削除します。
    *   削除処理は安全のため1件ずつ順番に行われ、処理中はボタンが無効化されます。
    *   **信頼性向上**: メニューの展開待ちやスピナー（ロード中）表示中の待機など、ネットワークやUIの遅延に対して堅牢な再試行ロジックを実装しています。
*   **SPA 対応**:
    *   YouTube のシングルページアプリケーション遷移（`yt-navigate-finish` イベント等）を検知し、ページ移動時にUIを適切にクリーンアップします。
    *   **二重起動防止**: 既にUI（フィルターパネル等）が存在する場合は初期化処理をスキップし、重複してインジェクトされるのを防ぎます。
    *   **厳格なURLチェック**: プレイリストページ以外（例: 個別動画ページ）に遷移した際は、UIを即座に削除し、誤動作を防ぎます。
    *   **パフォーマンス最適化**:
        *   **早期クリーンアップ**: SPA遷移開始イベント（`yt-navigate-start`）を検知した瞬間にオブザーバーを切断し、DOM破棄に伴うブラウザのフリーズを防ぎます。
        *   **待機処理の軽量化**: 要素の出現待機（`waitForElement`）には低負荷なポーリング方式を採用し、ページ構造の激しい変化による影響を最小限に抑えています。

## 5. データ構造とバージョニング

将来的な機能拡張（最終発見日時の記録など）に備え、保存データの形式をバージョニング管理しています。

### 5.1 旧データ形式 (バージョン表記なし)
初期実装で採用されていた形式です。プレイリスト ID をキーとし、動画 ID の配列を値に持つ単純なマッピング構造です。

```json
{
  "PL_ExampleId1": ["videoId1", "videoId2"],
  "PL_ExampleId2": ["videoId3"]
}
```

### 5.2 バージョン 1
データ全体をラッパーオブジェクトで包み、`version` プロパティと `playlists` プロパティを導入しました。

```json
{
  "version": 1,
  "playlists": {
    "PL_ExampleId1": ["videoId1", "videoId2"],
    "PL_ExampleId2": ["videoId3"]
  }
}
```

### 5.3 マイグレーション (移行処理)
スクリプトの実行開始時に `loadStorage` 関数がデータをチェックします。`version` プロパティが存在しない場合は旧形式（バージョン 0 相当）と判断し、自動的にバージョン 1 の構造へ変換して保存します。これにより、ユーザーの過去の記録を維持したまま、新しいデータ形式へ安全に移行されます。

## 7. データインポート機能

外部サーバー等にバックアップされたJSONデータを取り込むことができます。

*   **使用方法**:
    1.  Tampermonkeyのユーザースクリプトメニューから「Import Data from URL」を選択します。
    2.  データのURL（`http` または `https` で始まるもの）を入力します。
*   **仕様**:
    *   **対象フォーマット**: バージョン1形式（`{ version: 1, playlists: { ... } }`）のJSONデータのみサポートします。
    *   **重複排除**: ローカルに既に保存されている動画IDは無視され、新規のIDのみがマージされます。
    *   **CORS**: `GM_xmlhttpRequest` を使用しているため、クロスドメイン制約を回避してデータを取得できます。
