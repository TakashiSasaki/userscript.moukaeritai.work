スタートメニューに２つOutlookがあります。二つ目の、つまり下の方のOutlookの設定という項目を開くとOutlook for Windows と表示されます。
ChatGPT:

Rephrased (English)
“There are two Outlook entries in the Start menu. When I open the settings of the second one (the lower Outlook), it is shown as ‘Outlook for Windows’. What does this mean?”

結論から言うと、スタートメニューに並んでいる2つの Outlook は別物です。

上の「Outlook (classic)」

  • 従来からある デスクトップ版 Outlook（Win32 / Office版）

  • Outlook 2016 / 2019 / 2021 / Microsoft 365 に含まれるもの

  • PST/OST、COM アドイン、VBA、細かい設定が使える

  • 実体は OUTLOOK.EXE

下の「Outlook」＝ 設定画面で表示される Outlook for Windows

  • Microsoft が New Outlook と呼んでいる新アプリ

  • Windows 11 / Microsoft Store 経由で配布

  • 内部的には WebView2 ベース（実質 Outlook on the Web のラッパー）

  • 設定画面に出ている

    • サイズが小さい（20MB程度）

    • データ使用量がほぼ無い
      という点が典型的特徴

つまり、

「Outlook for Windows」＝ 新しい Outlook（New Outlook）
「Outlook (classic)」＝ 従来のデスクトップ版 Outlook

という関係です。

なぜ2つ並ぶのか

Microsoft は現在、

  • Classic Outlook を残したまま

  • New Outlook を並行配布
    しています。

そのため、

  • スタートメニュー

  • 「アプリと機能」

  • 既定のメールアプリ選択

のすべてで 2つの Outlook が共存する状態になります。

実務上の注意点

  • アドイン・PST・高度な運用が必要 → Outlook (classic)

  • 軽量・Webメール中心 → Outlook for Windows

  • 既定のメールアプリが New Outlook に切り替わっていると、
    mailto: リンクや他アプリ連携の挙動が変わることがあります。

整理した理解

  • 下の Outlook を開くと「Outlook for Windows」と表示される
    → 仕様どおり・正常

  • 不具合や重複ではない

  • 意図的な Microsoft の段階的移行設計

この状況はしばらく続きます。Microsoft は最終的に Microsoft Outlook の New Outlook への統合を狙っていますが、現時点では Classic 依存の機能が多く、完全移行には至っていません。

必要であれば、

  • 既定アプリの切り替え

  • New Outlook の無効化 / 非表示

  • 両者の機能差一覧

まで整理できます。

あなた:
Mirosoft Storeで更新ボタンを押すとエラーになっちゃった。
ChatGPT:

Rephrased (English)
“When I click the Update button in Microsoft Store, it fails with an error.”

表示されている 0x80073CF6 は、Microsoft Store アプリの更新処理が内部状態の不整合で失敗したときに出やすい汎用エラーです。今回の対象は **Microsoft Outlook（Outlook for Windows / New Outlook）**ですが、原因はアプリ本体というより Microsoft Store 側のキャッシュや登録情報であることが多いです。

以下は影響の小さい順に、実務的に成功率が高い手順です。

手順1（最短）

Microsoft Store のキャッシュをリセット

  1. Win + R

  2. wsreset.exe

  3. 黒い画面が一瞬出て Store が再起動 → 再度「更新」

手順2（推奨）

Store アプリの修復／リセット

  1. 設定 → アプリ → インストールされているアプリ

  2. Microsoft Store → 詳細オプション

  3. 「修復」→ 失敗したら「リセット」

  4. PC 再起動 → 更新再試行

手順3（Outlook 側を触る）

Outlook for Windows を一度アンインストールして再インストール

  • 設定 → アプリ → Outlook for Windows → アンインストール

  • Microsoft Store から再インストール
    ※ New Outlook はローカルデータをほぼ持たないため、実害はほぼありません。

手順4（PowerShell・確実）

Store アプリ登録の再登録（管理者）

powershell
Get-AppxPackage -allusers Microsoft.WindowsStore |
  Foreach {
    Add-AppxPackage -DisableDevelopmentMode -Register "$($_.InstallLocation)\AppXManifest.xml"
  }

再起動後に更新を試してください。

補足（重要な切り分け）

  • Outlook (classic) には影響しません

  • New Outlook（Store 版）は WebView2 依存のため、
    Store 側の不調＝更新失敗になりがち

  • メッセージにある

    「この問題は認識しており…」
    は Store 側の既知不具合テンプレ文言です

結論

  • あなたの環境固有の致命的問題ではない

  • wsreset → Store リセットで解決するケースが大半

  • 直らなければ 一度アンインストール → 再インストールが最短安定解

この状態でも Outlook (classic) は通常どおり利用できます。New Outlook を積極的に使う必要がなければ、更新に固執せず放置しても実害はありません。

ChatGPT:

Rephrased (English)
“After updating Outlook for Windows and clicking ‘Open’, I see this screen. The ‘New Outlook’ switch appears to be turned on.”

はい。その理解で正しいです。いま表示されているのは「Outlook (classic)」ですが、右上のスイッチが ON＝New Outlook モードで動作中です。

ポイントを正確に整理します。

  • 画面のリボン（ファイル／ホーム／表示…）や全体の構成は Classic Outlook の外枠

  • 右上の 「新しい Outlook」スイッチが ON
    → 内部的に New Outlook（Outlook for Windows）へ切り替えられている状態

  • その結果、実体は Microsoft Outlook（New Outlook） と同じ挙動になります
    （WebView2 ベース、PST/COM アドイン非対応など）

どういう設計か

Microsoft は移行期のために、

  • Classic Outlook を起点に

  • スイッチで New Outlook を起動する
    という“二重構造”を採っています。
    そのため、Classic を起動しても New Outlook が前面に出ることがあります。今回がそれです。

切り替え方法（確認用）

  • New Outlook をやめたい場合
    右上の 「新しい Outlook」スイッチを OFF
    → Outlook 再起動
    → 完全に Outlook (classic) に戻ります

  • New Outlook を使い続ける場合
    そのままで問題ありません。Store 版を直接起動した場合と実質同等です。

補足（よくある誤解の回避）

  • これは 2つの Outlook が同時に壊れて起動しているわけではありません

  • 更新に成功した結果として正常な状態です

  • 既定のメールアプリ設定や mailto: の挙動は、New Outlook 側が優先されます

結論

  • 画面の状態は想定どおり

  • スイッチ ON＝New Outlook 使用中

  • OFF にすれば Classic に完全復帰

どちらを使うべきかは、PST/アドイン/MAPI が必要かどうかで決めれば十分です。
