# バージョン番号に関する指示
- 少しでもコードに変更を加えた時には、必ずバージョンのパッチレベルをバンプアップすること。
- AGENTS.md は他の開発者やコーディングエージェントも参照するので、コーディングの過程で得た気づきを、特に他のコーディングエージェントが同じ失敗をしないように、書いておくこと。
- AGENTS.md は頻繁に更新すること。
- README.md はユーザースクリプトを実際に使う一般ユーザーにむけた使い方の説明を書くこと。

## 技術的知見 (Outlook Copilot DOM)

### 1. Iframe 内の要素特定
Outlook Copilot のチャット履歴や対話ダイアログは、通常トップレベルの document ではなく、動的に生成される `iframe` 内に配置されています。
- `findInFrames` のような再帰的に iframe を探索するヘルパー関数は必須です。
- トップレベルの `MutationObserver` だけでは、iframe 内部の状態変化（チャットの選択など）を検知できない場合があるため、`setInterval` による定期的なチェックを併用するのが確実です。

### 2. セレクターの信頼性
- **チャット履歴の選択状態**: `.fui-NavSubItem[aria-current="page"]` が最も信頼できます。単なる `.fui-NavItem` は「新しいチャット」ボタンなども含むため、意図しない場所で UI を表示してしまう原因になります。
- **削除確認ダイアログのタイトル**: `div[role="dialog"]` 内のタイトルは、単純な `<b>` タグではなく、Fluent UI のクラス（例: `fkhj508`）や、`font-weight: 700` が指定された `<span>` であることが多いです。

### 3. 文字列比較の注意点
- サイドバーのタイトルとダイアログ内のタイトルを比較する際は、空白文字や句読点（`...` や `?` など）の違い、大文字小文字の違いを吸収するために、正規化（スペース除去、記号除去、小文字化）を行ってから `includes` で部分一致を確認するのが安全です。

### 4. パフォーマンスの最適化
- **UI のドラッグ**: ドラッグ中の位置更新には `requestAnimationFrame` (rAF) を使用してください。これにより、ブラウザの描画タイミングと同期したスムーズな移動が可能になります。
- **MutationObserver の負荷**: `document.body` を `subtree: true` で監視すると、複雑な PWA では大量のイベントが発生します。各イベントで iframe 内を探索する処理（`findInFrames`）を実行すると、メインスレッドがブロックされ、ドラッグ操作などがガクつく原因になります。
  - `checkVisibility` のような重い処理は必ず **デバウンス** するか、`rAF` で実行頻度を制限してください。
  - ドラッグ中などの特定の操作中は、オブザーバーの処理を一時停止するガードフラグを設けるのがベストプラクティスです。

### 5. 初期化のタイミング
- **DOM 構築の待機**: Outlook のような重厚な PWA では、`DOMContentLoaded` や `load` イベントが発生した後も、内部の iframe やコンポーネントの非同期読み込みが続きます。
- ユーザースクリプトの開始を数秒（例: 2〜3秒）意図的に遅らせることで、要素がまだ存在しないことによる初期化エラーや、不完全な状態での DOM 探索を避けることができます。
- `@run-at document-idle` を指定した上で、さらにスクリプト内部で `setTimeout` を使用するのが最も安全なアプローチの一つです。

### 6. サイドバーの DOM 構造とナビゲーション
- **リスト構造**: 会話リストは `div.fui-NavDrawerBody` 内に `div` 要素（行）が並ぶ構造になっています。しかし、行の間に `<I>` タグ（区切り線）などの非対話要素が挿入されることがあります。
- **インデックスベースの取得**: 削除後に「次の会話」を選択する場合、`nextElementSibling` では非対話要素に当たってしまい「リストの末尾」と誤判定されるリスクがあります。
  - 対策: `container.querySelectorAll(SELECTOR)` で全対話アイテムを配列として取得し、現在のアイテムの **index + 1** 番目を取得する手法が最も堅牢です。
- **情報のキャプチャ**: DOM 要素だけでなく、**タイトルテキスト**も事前にキャプチャしておくことで、削除後の再レンダリングで要素が stale（無効）になった場合のフォールバック検索（`findByText`）が可能になります。
- **同期のウェイト**: 削除確定直後は UI が不安定なため、十分な待機時間（例: 1000ms）を設けてから次の会話をクリックしてください。
- **UI 状態の管理**: `window` オブジェクトを介したメソッド呼び出しだけでなく、スクリプト内のクロージャスコープで定義された状態管理オブジェクト（例: `copilotDeleterMethods`）を併用することで、非同期更新時の信頼性を高めることができます。
- **デバッグ用初期表示**: インジケーターは非表示にするのではなく「Searching...」などのプレースホルダーを表示することで、UI の存在をユーザーに明示し、動作中であることを視覚的にフィードバックできます。

### 7. ロード確認用ログ
- Outlook PWA では「スクリプト自体が未ロード」なのか「ロード済みだが iframe 内条件が未成立」なのかが見分けにくいため、ロード直後・監視開始・UI生成・UI非表示化の各段階で `console.log` を出しておくと切り分けが速くなります。
- 先頭にスクリプト名とバージョンを含む一貫したプレフィックスを付けると、Tampermonkey の複数スクリプトが同時に動いていてもログが追いやすくなります。


## `index.html` のメンテナンス要件

各階層（ルートディレクトリ、ドメイン別ディレクトリ、個別のスクリプトディレクトリ）の `index.html` は、最新の状態に同期して保つ必要があります。

1. **バージョン情報の同期**:
   - スクリプトのバージョンが更新された場合は、関連するすべての `index.html` 内にハードコードされているバージョン表記も忘れずに更新してください。
   - インストールボタンの構造は、動的なバージョン比較機能（Github上の最新バージョンとローカルのインストール済みバージョンの比較）のために、所定のDOM構造（`<div class="version-info">` 内に `.latest-version` と `.installed-version` を含む構造）を維持してください。

2. **依存関係とイベントの明記**:
   - 複数のユーザースクリプト間で連携する機能（CustomEventを用いたメッセージの送受信など）がある場合、スクリプトの紹介カードや詳細ページには、その依存関係（「送信先」「受信元」など）を明確に記載してください。

3. **ドキュメントの網羅性**:
   - 新しいスクリプト（システムローダーなどの裏側で動くスクリプトを含む）を追加した場合は、必ず該当するドメインの `index.html` およびルートの `index.html` の一覧にも漏れなく追加してください。
