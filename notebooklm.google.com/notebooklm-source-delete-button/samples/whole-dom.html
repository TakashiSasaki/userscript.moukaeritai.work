• 更新手続き: 引き続きサーバ証明書を利用する場合に、更新用のTSVファイルを作成します 。
• 失効手続き: シャットダウンや移行完了により証明書を利用しなくなる場合に、失効用のTSVファイルを作成します 。

◦ OS: Ubuntu 22.04.5 LTS (Jammy Jellyfish) 。
◦ ホームディレクトリ: /net/knas/homes/sasaki 。
• ストレージ構成:
◦ Linuxコンテナ内からは nfs4 (vers=4.0) プロトコルでマウントされている 。
◦ Windows環境からは Samba 経由で同じディレクトリを参照可能であり、作成したファイルの編集やアップロードを効率的に行える環境となっている 。
2. Linux作業ディレクトリの構造
作業ディレクトリ（例： ~/cert/epas/20260115 ）には、以下のファイル群が配置されています 。
• config : 証明書の主体者情報（DN）を定義する設定ファイル 。
• Makefile : make コマンド一発で秘密鍵や証明書要求（req）を生成できるよう自動化されている 。
• key / key.plain : 生成された秘密鍵。 key.plain はパスワードなし、 key は暗号化された鍵 。
• pass : 秘密鍵を暗号化するためのパスワードを保存するテキストファイル 。
• req / req.txt : 生成された証明書要求ファイル。 req.txt は内容を確認するためのテキスト形式 。
• epas-2025.cer : 過去（前年）の証明書データ 。
• update-server-[日時].tsv : NIIのTSVツールで作成された発行依頼用ファイル 。
• r1 , r2 , r3 : 作業過程で生成される一時ファイル群 。
3. 主体者情報（Distinguished Name）の設定
config ファイルにおいて、対象サーバの属性を正しく設定する必要があります 。
• 基本項目:
◦ C (Country): JP
◦ ST (State): Ehime
◦ L (Locality): Matsuyama-shi
◦ O (Organization): Ehime University
◦ CN (Common Name): epas.office.ehime-u.ac.jp 等、対象ホスト名 。
• 重要な制限事項:
◦ 2022年7月26日以降、 OU（部署名）を含む証明書の発行は不可 となっているため、設定にOUを含めてはならない 。
◦ 更新申請の場合、CN、OU、Cが過去の登録と一致していれば、LやSTが異なっていても受け付けられるが、愛媛大学の設定では通常上記の内容が標準となる 。
4. セキュリティと鍵の管理
• パスワード管理: 秘密鍵を暗号化するためのパスワードは、 pass ファイルに記述する 。
◦ 注意点として、 pass ファイルの末尾に 改行コードを付けない ことが求められている 。
• 暗号化: 秘密鍵の暗号化により、NAS上での安全な保管を担保している 。
5. ワークフローの統合
証明書取得までの全体フローにおいて、CSR作成は初期段階の重要作業です 。
1. Linux環境: SSH接続し、OpenSSLを用いて「鍵ペア・CSR」を作成する 。
2. Windows環境:
◦ NAS上の同一ディレクトリにアクセスし、NIIの TSVツール を使用してTSVファイルを作成する 。
◦ 愛媛大学指定の Excel申請書 を編集する 。
3. 提出: 作成したTSVファイルとExcel申請書を総合情報メディアセンター（CITE）の登録担当（ center@dpc.ehime-u.ac.jp ）へメールで送付する 。

TSVファイルに関して詳細な

2026年1月15日作成：サーバ証明書申請用TSVファイルに関する詳細レポート
本レポートは、提供されたソース資料に基づき、愛媛大学でのサーバ証明書（特に epas および yoran ホスト）の更新・失効手続きにおいて不可欠な「TSVファイル」の概要、作成方法、および提出手順について詳細にまとめたものです。
--------------------------------------------------------------------------------
1. TSVファイルの概要と役割
TSV（Tab-Separated Values）ファイルは、国立情報学研究所（NII）が運営する「UPKI電子証明書発行サービス」において、証明書の発行（新規・更新）や失効を依頼する際に必要となる 特殊な形式のデータファイル です 。
証明書の管理システム（TSVツール）へこのファイルをアップロードまたは登録担当者へ送付することで、一連の申請手続きが開始されます 。愛媛大学においては、後述するExcel形式の申請書とともに提出することが義務付けられています 。
2. TSVファイルの作成方法と専用ツール
TSVファイルを作成するには、NIIが提供する以下の専用ウェブツールを使用する必要があります。
• 作成ツール（TSVツール トップメニュー）: https://certs.nii.ac.jp/tsv-tool/
• 操作手順: NIIが提供する「TSVツール操作手順書」に従って作成を行います 。
3. 手続き別の利用ケース
サーバの運用状況に応じて、作成するTSVファイルの種類や申請内容が異なります。
• 更新申請: 引き続きサーバ証明書を利用する場合に行います 。
• 失効申請: サーバのシャットダウンや移行完了に伴い、証明書が不要になった場合に行います 。特に yoran.office.ehime-u.ac.jp は新システムへの移行が計画されており、停止時期が確定している場合は失効用のTSV作成が求められます 。
4. 更新申請時の主体者DNに関する重要ルール
2020年7月15日の仕様変更により、更新申請時に受理される「主体者DN（証明書の登録情報）」のチェックルールが緩和されています 。
• 一致必須項目: CN（常用名）、OU（部署名）、C（国名） 。
• 不一致許容項目: L（市区町村）、ST（都道府県） 。
• 注意: 2022年7月26日以降、新規および更新発行において OU（部署名）を含む証明書の発行は不可 となっています 。
一致必須項目が過去の登録と同一であれば、所在地情報（L, ST）が異なっていても「更新」として手続きでき、新規発行よりも手続きが簡略化されます 。
5. 愛媛大学における提出手順
作成したTSVファイルは、学内の登録窓口へ以下の通り提出します。
• 必要書類一式:
1. TSVツールで作成した TSVファイル
2. 愛媛大学総合情報メディアセンター（CITE）指定の サーバ証明書発行申請書（Excelファイル）
• 提出先: メディアセンター登録担当（情報推進課 情報技術チーム）
• 提出方法: メール添付（宛先: center@dpc.ehime-u.ac.jp ）または学内便 。
6. 研究室環境での管理状況
川原研究室のNAS環境（ 133.71.3.4 ）内では、秘密鍵やCSRの作成とともに、TSVファイルもディレクトリごとに管理されています 。
• 作業ディレクトリ例: ~/cert/epas/20260115
• ファイル名の例: update-server-202601151848.tsv や issue-server-202308101710.tsv のように、申請種別と日時を含む形式で保存されています 。
• 環境の利便性: Linuxコンテナ上で作成したTSVファイルを、Samba経由でWindows側から取得し、メディアセンターへメール送信する運用が行われています 。
